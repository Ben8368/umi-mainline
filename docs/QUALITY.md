# 质量与验收

| 层级 | 证据 | 不能证明 |
| --- | --- | --- |
| L0 静态 | 语法、文档链接、策略、署名、静态审查 | 内核可编译或硬件可运行 |
| L1 合成 | 隔离构建失败、打包、解析与模拟 API 回归 | I²C 写入实际成功、真实保护有效 |
| L2 编译 | 固定 Linux 树与工具链，C 驱动/DTB 编译结果 | 手机启动、温控、充电、文件系统安全 |
| L3 真机 | 指定设备、面板、内核/镜像哈希与测试记录 | 未测设备变种、长期稳定性 |

CI 的统一门禁是 CI result；必需任务必须 success，缺失、失败、取消和意外跳过都拒绝。具体接线见 [ci](ci.md)，真机矩阵见 [test-matrix](test-matrix.md)。

完成定义：范围明确、错误路径有回归、风险与延期实现登记、来源与许可证保留、真实验证命令及未覆盖项可追踪。开发权限保留不代表发布就绪。CI 与机器人审查不替代维护者审查、供电安全或真机验收。

## 分层审查与反例验证

CodeRabbit 是补充缺陷发现器；审查完成不证明没有漏报。开发者先给出行为契约、自查和测试，专项复核者追踪完整调用链，CI 检验可重复条件，维护者依据证据决定是否合并。决定见 [ADR 0006](ADR/0006-layered-review.md)；提交与远端门禁仍以 [AI_RULES](AI_RULES.md#pr-推送与远端验证) 为准。

| 风险 | 触发范围（按行为判断，改名和关联文件同样计入） | 合并前额外证据 |
| --- | --- | --- |
| 低 | 无行为变化的文案、排版、链接 | 开发自查、治理检查及常规 PR 门禁 |
| 中 | 普通工具、无保护含义的依赖、离线测试行为 | 调用者/错误路径检查，相关正反例；测试改动检查预期值独立性 |
| 高 | 内核/DT/固件、供电、启动/存储/多文件交付、CI/权限/治理门禁；改变上述验证或相关事实声明 | 开发者以外的专项复核记录、故障/恢复反例，适用的 L2/L3 或明确未覆盖与阻断边界 |

不确定时从高处理；纯文档若改变安全契约也属高风险。专项复核可由有相关能力的维护者或另一个只读审查会话完成；开发会话自查和 CodeRabbit 不计作该独立复核。审查会话只提供意见，不自动派单、写入、运行设备命令或获得合并权；上下文包含 base/head、完整 diff、调用者/清理路径、权威契约与测试。具体发起仍遵守本轮授权和机器人准入范围，不因本规则自动授权高风险 Jules 派单。

专项复核先独立分析，再对照 CodeRabbit 意见，重点回答：

1. 入口、单位、预算和状态转换是否一致？跟踪初始化 → 正常运行 → 故障 → 恢复/拔插/卸载，覆盖未改动的调用者。
2. 每个可失败操作的返回值和部分成功状态如何处理？是否先降载再协商、清理全部资源，发布中断后是否保留同一批产物？
3. 测试是否先断言已到达正常状态，再注入故障？除最终值外，是否观察中间写入、次数和顺序，能否抓到先错后恢复？
4. 预期值是否来自独立契约，而非复制实现？对修复的缺陷，在临时副本或内存中恢复对应旧行为，应使回归因目标断言失败；编译/依赖错误不算捕获缺陷。只对有实际价值的缺陷做此验证，不要求全库变异测试。

记录格式：复核者/会话、base/head 或未提交 diff 范围、调用链、发现与处置、命令/退出结果、未覆盖项及阻断边界。每个有效意见优先转为行为回归；无法离线证明的硬件假设留在风险台账，不能通过降低断言消除。大改动先按供电、交付、治理等可独立验证的行为拆分，默认仍交付一个面向主分支的 PR，不创建依赖堆叠 PR。
