# Linux 6.18.59 首次实机临时启动

日期：2026-10-29（Asia/Shanghai）。用户明确要求对已连接、处于 fastboot 的设备启动上一轮构建镜像。本轮范围为临时引导和只读诊断；未授权或执行持久刷写、切根、分区修改或主动充电。

## 输入、身份与回退

- 镜像：`out/linux-6.18.59/boot-umi-6.18.59.img`，17,248,256 bytes，SHA256 `643826293cfb680319e239569657ac788387a31adbafdbfc62e460ff861420b7`，与[构建记录](2026-10-29-linux-6.18.59-build.md)一致。
- Windows x64 / PowerShell 7.6.5；Android platform-tools fastboot 37.0.1。选定单台设备并核对 `product=umi`、`unlocked=yes`、`is-userspace=no`。
- 启动前再次核验 gzip/arm64、三份 DTB 符号、Wi-Fi DTB 的 BQ25970=disabled、实际 initramfs 的 `root-dev=none` 及构建副本一致性，验证脚本 exit 0。
- 仅用 `fastboot -s <本机序列号> boot <镜像>`；未执行 flash/erase 或槽位变更。回退方式为电源键加音量下返回 fastboot，随后可启动原 boot；本轮未覆盖原 boot。既有 boot 备份的来源见[PPS 设备记录](2026-10-29-pps-device-flash.md)，本轮未重新核验整分区哈希。

## 执行与读回

第一次先 `reboot-bootloader` 清除会话状态，再临时启动：Sending / Booting 均 OKAY，exit 0。设备出现 UMI-MAINLINE USB RNDIS/CDC-ACM；用户反馈黑屏并手动回到 fastboot，首次打开串口因设备已重启而失败，不能据此判断内核崩溃。

第二次临时启动同一镜像：Sending / Booting 均 OKAY，exit 0；自动等待 USB 串口后立即通过 COM4 收集日志。读取证据：

```text
uname: Linux (none) 6.18.59-umi-dirty ... aarch64 Linux
root-dev: none
compatible: qcom,kona-mtp / qcom,kona / qcom,mtp
[23.750799] UMI-INIT: shell is running on /dev/ttyGS0
[23.877920] UMI-INIT: kernel is alive and user space is running.
```

`/proc/mounts` 只见 rootfs、proc/sysfs、devtmpfs/devpts、tmpfs、debugfs/configfs；没有 userdata 或其他 UFS 文件系统挂载。未发送主动 PPS、充电启用、寄存器或真实块设备写命令。

## 结果与未通过项

| 项目 | 结果 | 证据与边界 |
| --- | --- | --- |
| fastboot 临时加载 | passed，两次 exit 0 | 不等于完整功能验收 |
| 6.18 内核进入救援用户空间 | passed | COM4 的 uname、init 结束与 shell 命令读回 |
| 救援根与调试通道 | passed | root-dev=none、挂载列表、COM4；RNDIS 已枚举，IP/SSH 未测 |
| 内建显示链/点亮 | failed | 用户反馈黑屏，UBWC 无匹配，MDSS probe=-22；只有 simpledrm card0 / fb0=1080,2340，不证明面板工作 |
| 触控 | blocked | 日志反复 `panel not ready yet, deferring probe`，13-0049 在 devices_deferred；未做触摸事件验收 |
| GPU / Wi-Fi / 桌面 | not-run | 无可用 MDSS，Wi-Fi 模块闭包仍未提供；未切根桌面 |
| PPS / 温控 / 充电功率 | not-run | 仅只读状态，不能视作供电验收 |

黑屏的直接阻断：ABL 覆写根 compatible 后，上游 UBWC 仅有的 SM8250 匹配失效；日志为 `Couldn't find UBWC config data for this platform!`，随后 `msm-mdss ... failed with error -22`。下一步应在源码中提供有依据的 kona/SM8250 匹配，再重编临时测试；本轮未修改 Image 字符串、UBWC 或供电配置。

另见 SPMI 0-00/01/02/03/04/05/0a/0b 重复 sysfs 设备产生 -EEXIST/-17 与调用栈，以及 ramoops header ECC 错误；本轮没有将它们归因于内核 panic，需继续排查 ABL overlay 与原生 PMIC 节点的重复实例。风险保持在 [RISK-002](../../RISK_REGISTER.md)。

SMB5 只读结果：`enabled=0 active=0 fault=0 error=0 inhibited=0`，`online=1 contract_uv=5000000 contract_ua=0 max_ua=1500000`，health=Good。这不构成活动 PPS 合同或充电安全证据。

原始 fastboot、串口和完整 dmesg 保存在忽略目录 `out/linux-6.18.59/device-*.log`；仅此摘要入库。测试后保持第二次启动的救援环境供后续诊断，未自动重启或刷写。本轮没有产品源码变更、提交、推送或 PR 操作。
