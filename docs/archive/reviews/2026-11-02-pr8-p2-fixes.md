## 已证实缺陷及处置

### P2-1 IRQ 屏蔽所有权

旧交错：threaded IRQ → error handler → reset/powercycle → disable（count=1）；外部 uninstall/reset/PM disable 看到 count=1 不增加 depth → 锁外 synchronize_irq；IRQ 恢复 enable 清空唯一 depth → 外部返回时已启用。该交错证明屏蔽契约失效，但 free_irq 仍独立排空，不据此虚报 remove UAF/P1。

新模型：fts_int 保护每设备两个幂等 owner：irq_external_disabled（所有外部控制调用）和 irq_recovery_disabled（当前设备 IRQ 线程）。每个 owner 最多持一个内核 disable depth；enable 只释放本域，重复 reset/retry 不累加。外部控制域是既有控制策略的幂等状态，不承诺多个任意外部诊断事务互斥；TD-009 的诊断并发限制不变。

- disable：锁内 disable_irq_nosync + owner 状态；释放 spinlock 后才允许 synchronize_irq。本设备 IRQ 线程始终跳过自等待。
- install：IRQF_NO_AUTOEN 提供初始 depth=1，交由外部 owner；删除直接清零计数的 API。request 之前不操作不属于本设备的 IRQ descriptor。
- 正常初始化/恢复：外部 enable 仅释放外部层；watchdog/ESD/hard-fault enable 仅释放恢复层。两种先后顺序的重叠仍保留外部层，合法外部 enable 后回到 depth=0。
- remove/probe unwind：stop idle、停止入口及 work → 外部 disable/drain → free_irq → 清注册状态和 table/input/info。恢复线程可以结束，但不能解除外部层；不存在持 fts_int 等待 IRQ 的环。
- shutdown/系统 PM：保持先前可选 idle 屏障，不顺带新增完整 sensing/IRQ PM 策略；无完整真机 PM 安全声明。

直接调用者已重查：fts_system_reset（ftsError、ftsFlash、ftsTest、cleanUp、init/recovery 的间接调用）、fts_chip_powercycle、fts_interrupt_install/uninstall、fts_resume_work、fts_suspend_work、enterGestureMode。唯一 NoSync 调用者仍为同步 wrapper。诊断 fwupdate 的原生 disable_irq/enable_irq 配对不改；它保有独立内核 depth。input_report_mutex/gestureMask_mutex 不跨同步停 IRQ；idle_lock 在 cancel/drain 前释放，idle 写入只进入 I²C transfer，不反向取得 fts_int。

### P2-2 GPIO 部分失败回滚

旧链：probe → set_gpio → request 成功 → direction 失败直接返回 → gpio_ready=false，公共 unwind 跳过释放。新实现仅在方向失败时跳到本次 request 的 free_gpio，保留原始 errno；request 本身失败不释放。reset 方向失败时，上层仍释放先前成功的 IRQ GPIO，并将 reset 编号失效；无重复 free。

6.18 legacy request 的无 descriptor 行为是 -EPROBE_DEFER，测试按真实内核契约建模，包含 IRQ/reset 请求失败及负 GPIO 编号；不误用 -EINVAL 替身。7.x 描述符分支不调用 legacy gpio_free，保持 devm 所有权。
