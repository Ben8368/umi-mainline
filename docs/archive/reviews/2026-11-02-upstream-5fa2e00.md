## 开发自查与调用链

复核者：本开发会话 Codex，自查不算 QUALITY 要求的独立专项复核。范围：上述 base 到本 PR 的完整修改；新增 fts.c/fts.h/ftsCore.c 状态机与测试。

1. probe 在任何可失败的硬件步骤之前初始化 idle work/锁。init_flow 包住 reset、校准及 init_sensing；sensing 保留 sense-off/等待/sense-on 与 IRQ 初始化。只在整条链成功后排队；失败仍保持设备绑定和 sysfs 恢复能力。
2. fts_system_reset / setScanMode 在库层先 hold；外层 mode_handler、恢复及诊断可以嵌套。不同控制线程交叠时不推断最终状态，保守停止重排队，等待下一次明确成功的正常扫描/初始化。hold 先使状态不可写，释放锁后同步取消；callback 在同一互斥锁下检查状态和发命令。callback 不调用 hold，不等待 IRQ 或事件队列，没有取消自身的路径。
3. reset 单独成功也不代表已经 sensing；必须等已知成功的正常扫描。ESD/watchdog 恢复累计错误；供电循环不会将早期 rail 错误被后续成功覆盖。fwupdate 结束保守不重排队，见 TD-009。
4. 系统 PM prepare/complete 只屏障可选 idle 命令；其他状态转换使保存的 readiness 失效，避免休眠期间失败复位后恢复旧状态。已有 fb blank/sensing/电源策略保留。
5. remove / shutdown / probe unwind 先设置不可恢复的 stopping 并同步取消；正在执行的 I/O 必须结束才继续。IRQ/notifier 按登记状态清理，IRQ 释放在 dispatch table 释放之前，重复初始化不再次注册。
6. I²C 错误只报告失败，不额外排队；底层 fts_write 原有有限传输重试不变。无动态扫描频率命令，无新固件，无真实设备命令。
