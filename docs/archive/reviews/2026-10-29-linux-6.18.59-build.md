## 命令与适配改动

```sh
git clone --depth 1 --branch v6.18.59 --single-branch \
  https://github.com/gregkh/linux.git /root/linux-6.18.59
cd /root/umi-6.18.59-work
TREE=/root/linux-6.18.59 OUT=/root/linux-6.18.59/out-umi \
  JOBS=12 TC=gcc sh scripts/build.sh
```

`scripts/build.sh` 自动注入项目 DTS、面板/触摸/供电驱动、GPI EE offset 与 power_supply 属性补丁。本轮没有更改供电参数、固件或默认内核目标。

面板驱动在 `devm_drm_panel_alloc` 分支误用 NULL 检查。6.18.59 的 API 明确返回 `ERR_PTR`，现改为 `IS_ERR` / `PTR_ERR`，旧内核 `devm_kzalloc` 分支仍检查 NULL。新增实际分配代码片段的故障注入，覆盖成功、ENOMEM 和托管分配错误传播；修复前新 API 路径发生 SIGSEGV，修复后通过。

首次构建在 `fts521/fts.c:3240` 报 `FB_EVENT_BLANK undeclared`：6.18.59 已移除该事件，既有 `>= 7.0` 判断遗漏了这一版本。改用 `#ifndef FB_EVENT_BLANK` 特性探测，缺少事件时使用原有空回调分支，保留 PM 行为；旧接口继续忽略 blank 通知，避免合成器 DPMS 导致触控永久 suspend。新增实际回调片段的双接口编译/执行回归，修复前缺少事件的路径失败，修复后通过。

第二次构建通过触控后，在电量计驱动报 `devm_power_supply_get_by_phandle` 未声明：原兼容宏以 `#ifndef` 检测函数名，始终覆盖新 API。核对上游 v6.16 / v6.17 头文件后，将旧别名限制在 `< 6.17`，并显式包含 `linux/version.h`。增加 6.12 / 6.16 / 6.17 / 6.18 / 7.2 的实际兼容片段回归，检查参数以及成功、NULL、EPROBE_DEFER 返回值保持不变；未修改充电参数或寄存器行为。

第三次构建通过电量计后，SMB5 驱动的直接 `devm_power_supply_get_by_phandle` 调用暴露同一 API 移除问题；将调用统一为 reference 名称，并使用相同的 `< 6.17` 兼容边界，回归覆盖两个驱动。上游接口依据：[v6.16 头文件](https://github.com/torvalds/linux/blob/v6.16/include/linux/power_supply.h)、[v6.17 头文件](https://github.com/torvalds/linux/blob/v6.17/include/linux/power_supply.h)。
